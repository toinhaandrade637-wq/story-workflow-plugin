# 影视全流程 · 分诊

## 14 段工序

段数与名称以 `mcp-server/stages.ts` 为准（这份表是它的投影，不是第二份真相）。
**不要凭记忆数段**——拿不准就调 `project_status` 或 `stage_spec`。

| 段 id | 段 | 交什么 | 本形态不走时 |
|---:|---|---|---|
| `setup` | 1 立项 | 立项定位表 + 故事核十维 + 首集双引擎 | — |
| `bible` | 2 总论 | 九编式总论（世界观 / 大纲 / 结构 / 主创阐述） | 小说叫「故事圣经」 |
| `life` | 3 生活场 | 五感生活场四维表 + 十条运行铁律 | — |
| `character` | 4 人物小传 | 一人一档（六章制）**每个角色一份** | 小说叫「人物圣经」 |
| `scene` | 5 场景 | 一景一档（9 参数 + 3 轴线）**每个场景一份** | — |
| `prop` | 6 道具 | 母题道具编码 + 流转状态 | — |
| `episodes` | 7 分集大纲 | 全局分集大纲（电影叫「分幕与节拍」，小说叫「分卷与章纲」） | — |

## 怎么用这套东西

**每段都要落成文件，不能只在对话里说。**

```
1. 调 project_status        → 看现在到哪段、下一段是什么、哪些段本形态不走
2. 调 stage_spec            → 取这一段的判据和小节结构
3. 调 create_deliverable    → 生成 markdown 骨架
4. 填内容
5. 调 check_deliverable     → 看哪些必填小节还空着
6. 调 judge_deliverable     → 过判据；SKIP 的项如实说明「机器判不了」
```

## 可以跳，但要说清代价

2026-11-12 修：原来这里写「不跳段」，与界面的「并行生长」直接冲突——
UI 允许用户横向点亮任意模块，Skill 却告诉 AI 不许跳，两边打架。

现在的规则：

1. **允许从任意段进入。** 用户说「先给我写第三集剧本」，就写。
2. **跳过的段要留痕。** 明确说「第 4 段人物小传还是空的，剧本里的人名和造型我只从总论取，
   可能有对不上的地方」，并建议补哪一段。
3. **跨段修改要查影响面。** 改了人物名/职业/伤效，下游的人物档、场景档、分集、
   剧本、分镜都可能要跟着改；先列清单，再逐条问用户要不要改。
4. **这不等于鼓励跳。** 有下游依赖的段（人物 → 剧本、分集 → 剧本、剧本 → 分镜）
   跳过会让后来的返工量翻倍，这时要劝一句。

## 账本随写随记，不攒到最后

**跨集信息是「写的时候记的」，不是「最后补的」。** 写到 EP10 的时候，没人记得 EP02 的疤在左边还是右边；等第 14 段再回头补，只能靠回忆，回忆必然出错。

| 账本 | 文件 | 什么时候写 | 谁写 |
|---|---|---|---|
| 锁定设定（L2） | `_state/locked.md` | 一确定就锁（形态、体量、人物名、疤的位置、场景拓扑） | `lock_setting` |
| 决策记录（L3） | `_state/decisions.md` | 每做一次重大决定 | `record_decision`（必须写为什么） |
| **跨集连续性账本（L2.5）** | `_state/continuity.md` | **每写完一集当场追加一行** | `append_continuity` |
| 伏笔台账 | `08-细节/伏笔与闲笔.md` | 埋一条记一条、收一条销一条 | 直接改文件 |

### 写每一集的固定动作

```
1. read_continuity(ep = 这一集)   → 读「上一集末」的四项状态
2. 写剧本
3. append_continuity(ep, time, place, look, prop)
                                  → 只写这一集**变了**的东西，没变写「—」
```

**为什么只写「变了」的**：复制上一行是穿帮的温床。上一行写「左额有疤」，这一集疤消失了，复制过来就永远发现不了。

### 第 14 段不是「重写账本」，是「对账」

终检拿 `_state/continuity.md` 逐行跟**剧本 / 分镜 / 人物档 / 场景档**四处核；核出的冲突写成「核对结论」，指到具体集与场。账本本身随集记录，终检只负责发现「账本与正文不一致」。

调 `continuity_gap` 查差集：剧本写了、账本没记的集，就是「写了没记」，下一集一定穿帮。

## 六条不许破

1. **交付物落盘，不只在对话里说。** 说完了没有文件，等于没做。
2. **不写形容词。** 「善良」「隐忍」不算内容；要写「他做了什么，让人看出这一点」。
3. **人物小传的「内心真软肋」不许空。** 这是全流程最容易漏、也最要命的一格。
4. **伤效必须在左右侧 + 部位 + 厘米数。** 「手臂上有一道疤」不算。
5. **道具必须有唯一编码。** 没有编码的道具，下一集会变。
6. **单本/单作者不等于规律。** 说「一般都这么写」之前要能说出样本数。

## 判据分两档，别混

- **硬规则**（格式、连续性、字段完整性）：可机器判，FAIL 就是错的，必须改。
- **审美建议**（节奏、留白、台词是否有力）：只能给人看，机器判不了就标 SKIP，
  不许伪装成 FAIL。好剧本不是填完最多表格的剧本。

## 方法成熟度要标出来

人物小传、场景、分集、分镜、终检这五段的方法本身还不完整。
写这五段时**要主动告诉用户**：「这一段的方法还不完整，我给的骨架可能漏东西。」不许假装齐备。

## 不做什么

- 不判断「好不好看」——那要真实读者盲评
- 不提供市场数据、平台热度、收视预测
- 不做「找几本类似的书」（那是检索，不是工序）
- 不冒充某位在世编剧/导演的语气说话（法律风险，见 docs/research/07 §二.5）
