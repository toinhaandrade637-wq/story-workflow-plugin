# 第三步 · 剧本正文

## 这一步要交什么

一段**能交出去的剧本正文**。不是大纲、不是梗概、不是「场景描述」。

| 交什么 | 判据 |
|---|---|
| 场次头 + 动作 + 台词 | 三样齐，格式统一（专业剧本格式 .fountain） |
| 单场体量 | 500–2,245 字之间（中位 825） |
| 台词 | 每句同时给「新信息 + 暴露说话人」 |
| 全篇不过 3,000 字 | 超过就是写了多场，拆开 |

## 格式：只有一套（专业剧本格式 .fountain）

磁盘上写 `.fountain`，**没有第二种格式**。

> **上游依据**：内置技能 `fountain-screenplay` v1.1.3（displayName「专业剧本格式」）。
> 磁盘写法、预览定类、反例都以它为准：
> `built-in-skills/fountain-screenplay/SKILL.md` + `references/preview.md` + `references/test-prompts.md`。
> 本页只是在本项目语境下把它收敛成**更严的一套**——技能允许的写法里，本项目只选一种，
> 避免同一仓里混用两种而显得「格式不统一」。

| 元素 | 磁盘怎么写 | 备注 |
|---|---|---|
| 标题页 | `Title:` / `Episode:` / `Logline:` / `Notes:` | 技能用例 ① 要求这三项齐全（可另加 `Author:`） |
| 场次头 | `内景. 老街 - 夜` / `外景.` / `内外.` | 子地点用连字符：`酒店-大堂` |
| 动作 | 普通段落 | 含冒号的叙述行要用 `!` 钉住（见下） |
| 台词 | `张三：你好。` | **不要人名独占一行，也不要用 `@张三` 分行式** |
| 声音 | `张三os：…` / `李四vo：…` | `os`=不是人物开口（画外/内心/电话）；`vo`=叙述旁白 |
| 括注 | `张三（低声）：…` | 闪回、年龄、身份等也放这里 |
| 字幕 | `【字幕：三年后】` | 不写 `字幕：` |
| 闪回场 | 场次头行尾 `（闪回）` | 场号自动成 1A |

### 台词为什么只选行内式（不用 `@名字`）

`fountain-screenplay` 两种都允许（SKILL.md 第 54 行：中文 `@张三` 或 `张三：台词`）。
但**本项目只选行内式**，三个理由：

1. 一行就是一句台词，不会出现「名字一行、台词一行」的空角色框；
2. 更接近中文行业剧本的读法；
3. 本应用只读解析、**不写回**（`ui/src/lib/fountain.ts` 里没有 `docToFountain`），所以不会被改回 `@`。

> ⚠️ **2026-11-11 的真实事故（写在这里防再犯）**
> 统一台词格式时，第一版用「名字里含 了/着/地/把/被 就是动作句」来防误判，
> 结果把真实角色名 **「赵了」** 整集拦掉，24 集共丢 **379 句台词**。
> 教训：**名字里出现什么字，不能当判据。** 中文人名可能含任何字——
> 「赵了」「地理老师」「被抢大妈」都是合法角色名。
> 正确做法：先把全仓 `@名字` 收成白名单，在白名单里的直接认作台词；
> 不在白名单的，才按「超长 / 带引号 / 空正文」这类**与字无关**的特征筛。

### 一条转换命令（脚本在 `tools/`）

```bash
node --experimental-strip-types tools/unifyDialogue.ts <工作区>/09-剧本          # 转换
node --experimental-strip-types tools/unifyDialogue.ts <工作区>/09-剧本 --dry     # 先看量
node --experimental-strip-types tools/backfillLogline.ts  <工作区>/09-剧本          # 补 Logline
node --experimental-strip-types tools/verifyFountain.ts                              # 技能 12 条验收
```

转换后**必须**核对两件事，缺一不可：
1. 场数不变（与分镜对账）；
2. 台词逐条等价（不能只看总数——总数接近但内容错位也是丢稿）。

**中文 / 好莱坞只是观感**，切换不改文件、不改元素类型。观感只影响导出：
- 中文导出：动作段加 `△`、场次下写 `人物：A、B`、字幕补书名号
- 好莱坞导出：等宽、角色名居中、不加 `△`、不写人物行

**磁盘里不写 `△`。** 那是 PDF/Word 导出时才加的。

### 一个必踩的坑：含冒号的动作行

Fountain 判台词的规则是「冒号前是一个短名字」，它不看语义。所以：

```
他喊道：不要走。        ← 会被当成「角色=他喊道，台词=不要走。」
!他喊道：不要走。       ← 加 ! 钉住，这行就是动作
```

**规则：凡是动作段里出现中文或英文冒号，行首加 `!`。** 同理，行首以 `.` 开头会被当成场次头，也要钉。

**混用的表现**：场次头写 `1-1　外　老街 — 夜`。**这是旧格式，已经不用了。** 动作里写「镜头推近」也不行——镜头术语属于分镜。

## 写作六步

| 步 | 做什么 | 完成判据 |
|---:|---|---|
| 1 | 读细纲，确认这一场承担哪种戏 | 说不出「这场承担什么」就别写 |
| 2 | 定场首场尾：进场时人物要什么，出场时变成什么 | 两头一样＝这场白写 |
| 3 | 写动作段：只写**能被拍到**的 | 出现「他意识到」＝改 |
| 4 | 写台词：先定「这句给什么新信息」，再定「谁会说这句」 | 两个都答不出就删 |
| 5 | 标声音归属：谁在说话、是不是画外/内心、有没有括注 | 该 `os` 的写成台词，人物就错了 |
| 6 | 过断言 | 见下 |

## 三变测试（判断这场该不该存在）

一场戏，三样里**至少变一样**：

| 变什么 | 问 |
|---|---|
| **筹码** | 赌注变大了吗？ |
| **知情边界** | 谁知道了什么，变了吗？ |
| **信任度** | 两个人的关系，变了吗？ |

**三样都没变，这场就是过场，删掉或者合并。**

## 抽象感受要翻译成可见解剖

AI 不能渲染"心碎"这种内部概念，它只能渲染可见的解剖和微表情。人也一样——写"他心碎了"，摄影师拍不出来。

**三组现成翻译**（可直接当判据用）：

| 抽象 | 可见的 |
|---|---|
| 心碎 | 湿眼、屏息、咬紧下颌、强迫静止 |
| 走神 | 空洞凝视、姿态松垮、反应延迟 |
| 温柔但有防备 | 柔和目光接触、极小幅度微笑、双臂仍交叉 |

**自查**：动作段里出现任何一个"情绪词"，就把它换成"身体在做什么"。
不是"他很紧张"，是"他把杯子放回桌上，放了两次才放稳"。

## 台词的硬要求

### 每句台词必须给两样

1. **新信息**（观众不知道的事）
2. **暴露说话人**（这句只有他会说）

**两个都答不出，删。** 只有一项，是过场台词，允许但要有理由。

### 最重的情绪，用最短的句子

长篇大论解释痛苦，是在削弱痛苦。

| 弱 | 强 |
|---|---|
| 「你知道吗，这些年我一个人带着孩子，每天起早贪黑，我真的太累了，我有时候真的撑不下去了……」 | 「我不累。」 |
| 「我恨你，你毁了我的一生，我永远不会原谅你」 | 「你走吧。」 |

### 让人不能直说，话才有劲

一个人**能直说却选择绕**，那句话才有潜台词。全都直说，就是说明书。

## 10 道格式断言（交稿前逐条过 · 就是 judge 的 F-01~F-10）

| # | 断言 | 不过的表现 |
|---:|---|---|
| F-01 | 场次头写成 `内景. 地点 - 日` | 写成 `1-1　外　地点 — 夜`（旧格式） |
| F-02 | 动作段零 △ / ▲ | 磁盘里写了 △（那是导出才加） |
| F-03 | 台词写成 `人名：台词`，不人名独占一行 | 人名单独一行 → 会被当动作 |
| F-04 | os/vo 黏在人名后，不写 (V.O.) | 写了 `(V.O.)` → 分不清 os/vo |
| F-05 | 字幕写成 `【字幕：…】` | 写成 `字幕：…` → 会被拆成角色行 |
| F-06 | 不写 `人物：A、B` | 本场人物由台词块推导，手写会变动作 |
| F-07 | 零 Markdown 标题 / 列表 / 表格 | `# 第一场` 会被当动作 |
| F-08 | 动作段零心理动词 | 出现「他意识到」 |
| F-09 | 动作段零镜头术语 | 出现「特写/全景/推镜/摇镜」 |
| F-10 | 场次数与台词量自洽 | 场次头漏写、台词被吞 |

**最容易违反的两条**：F-08 心理动词、F-09 镜头术语。实测 24 集成品里 F-08 有 4 处、F-09 未出现——但每稿都要主动查。

**F-03 的口径**：A 说 B 答不算「连着」，算两块。同一个角色连着说 4 块以上要拆。

## 可拍断言（能机器判的三条）

| # | 断言 | 怎么查 |
|---:|---|---|
| 1 | 零心理动词 | 搜「感到/意识到/心里/内心/暗想/明白过来/恍然大悟」 |
| 2 | 零抽象总结 | 「他们的关系从此改变了」这类句子 |
| 3 | 每场有可拍锚点 | 至少一个具体的物件/动作/声音 |

**判不了的，别假装能判**：
- 「每个情节点可被拍出来」——只能查心理动词，查不出真正的可拍性
- 「道具与状态连续」——需要跨场状态机
- 「台词能听出是谁」——需要语感判断

## 两条外来硬规则（出自 SceneFlow 的实战提示词）

这两条是别人踩坑踩出来的，不是理论——

### 规则一：逐字回指，不许改写

台词或动作如果要被下游引用（分镜、cue 表、审片记录），必须**逐字**能在这份剧本里找到。

不许：
- 换个说法（"他说他不想去" ← 原文是"我不去"）
- 改标点（把"？"改成"。"）
- 拼接两句（原文分两行，引的时候合成一句）

理由：任何"引用"都要能被机器检索回原文。改了字就断链，后面所有对账（剧本↔分镜↔成片）全部失效。

### 规则二：时间码是「分:秒」，不是小数

写 `01:23.3` 时，它是 **83.3 秒**，不是 123.3 秒。

换算永远显式写：

```
01:23.3 = 1×60 + 23.3 = 83.3 秒
02:10.0 = 2×60 + 10.0 = 130.0 秒
```

理由：语言模型会把 `01:23.3` 当成 123.3 处理（把冒号当小数点）。这条坑在 SceneFlow 的提示词里被标成 **CRITICAL**。

## 常见失败

| 症状 | 病因 | 改法 |
|---|---|---|
| 读起来像小说 | 写了「他感到」「他知道」 | 换成动作：他做了什么，让别人看出他知道 |
| 台词都在解释剧情 | 角色在替观众总结 | 删掉解释，让动作说 |
| 场场都紧张 | 没有呼吸 | 每 3–4 场放一个轻场，用轻盈消解沉重 |
| 交了但被退 | 格式不统一 / 有镜头术语 | 过 8 道断言 |

## 交稿前

逐条过 10 道格式断言（F-01~F-10）+ 3 条可拍断言。**过了才算完成。**

交稿后跑一次 `judge_deliverable`，不要自评。要给人看就 `export_docx`（中文观感带 △ 与人物行）。

**但记住**：这个插件只能保证「形状对」。**写出来能不能看，要真实读者判**——不要说「已经写好」，说「形状对了，请人过一遍」。
